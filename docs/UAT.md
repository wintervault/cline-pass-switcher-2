# 手动验收清单（UAT）

> 单元测试全部 mock 了上游（零网络、零额度），所以**真实网关行为**必须用这份清单手动验收。
> 每项都标注了预期结果；带 💰 的会产生极小额真实请求（单次约 $0.0002 级）。
> 旧版 `server.js` 已随 v2.0.0 移除；如需对照可从 git 历史取回。

## 准备

- [ ] `npm install`
- [ ] `npm run build`（server + web）
- [ ] `npm start`，浏览器打开 `http://127.0.0.1:3123/`
- [ ] 在「账号池」添加真实 Cline Pass 账号（`sk_` 开头）并保存

## 1. 数据可靠性与启动行为（零额度）

- [ ] **损坏恢复**：把 `metadata.json` 内容改成 `{}`，重启 → 服务正常启动、聊天接口不 500、日志有 warn
- [ ] **配置备份**：把 `config.json` 截断成非法 JSON，重启 → 生成 `config.json.broken-<时间>` 且原内容完整保留在备份里，服务用默认配置启动
- [ ] **安全闸门**：`BIND_HOST=0.0.0.0 npm start`（proxyKey 为空）→ 拒绝启动，报错给出三种修复方式
- [ ] **优雅退出**：发起一条流式请求进行中时 `Ctrl+C` → 等在途请求结束后退出，日志出现「数据已落盘」「已优雅退出」
- [ ] **配置迁移**：用旧版（v1.2）的 `config.json`（含 `apiKey`、`perModel[].upstream`、`accountMode: roundrobin`）启动 → 自动迁移，日志列出迁移项，账号与钉住配置完好

## 2. 安全（零额度）

- [ ] **鉴权**：设置下游密钥后，无密钥访问 `/api/models` → 401；带密钥 → 200；`/healthz` 免鉴权 → 200
- [ ] **掩码**：`/api/accounts` 不含明文 key，只有掩码与末 4 位
- [ ] **跨源拦截**：在任意其他网页的 console 执行
  `fetch('http://127.0.0.1:3123/api/config', {method:'POST', headers:{'Content-Type':'application/json','X-Admin-Key':'<你的密钥>'}, body:'{}'})`
  → 被拒（403）
- [ ] **密钥不丢**：在「账号池」编辑账号名称但不重填 key，保存 → key 保持原值

## 3. 探测与渠道清单 💰

- [ ] 对任一订阅模型点「探测」→ 模型行出现管道徽章（Vercel/OpenRouter），上游数 > 0，
      上游清单里**包含本次实际命中的渠道**（执行链解析，含链首）
- [ ] 点「校验」→ 各渠道标注 ✔可用 / ⏳限流 / ✘不可钉，下拉框与面板排序生效
- [ ] **探针判定**：探测后模型行不出现「⚠ 钉住参数被网关忽略」→ `pinState=enforced`，
      「校验」可用；若出现该徽章 → 「校验」置灰、渠道面板顶部有告警
      （若你的账号被风控，这是**正确**行为——换个账号对比）
- [ ] 点「⬇ 拉取官方最新模型」→ 有新增则高亮，无新增提示已是最新

## 4. 钉住与故障转移 💰

- [ ] **严格钉住**：勾选一个可用渠道 → 「测试」→ 实际上游 = 目标渠道
- [ ] **钉住审计**（需 pinState=enforced）：把目标换成一个「会被网关忽略/绕过」的渠道 →
      「测试」→ 尝试序列出现「钉住未生效：…」并自动切换下一候选；全部候选都不听话时
      返回失败且错误信息说明钉住未生效
- [ ] **流式审计标记**：strict 钉住发流式请求，若网关未按目标服务 → 历史页该条记录
      出现「⚠ 钉住未生效」红标（流式不撤回，只标记）
- [ ] **故障转移**：勾选两个渠道，把第一个换成不可钉的渠道 → 「测试」→ 尝试序列显示
      `不可钉(✗400/502) → 可用(✔)`，最终成功；第一个渠道进入冷却（冷却期后再看候选顺序已沉底）
- [ ] **排除**：勾「排除」某渠道后「测试」→ 实际上游不是被排除的渠道；
      未探测过的模型上排除会提示「无法生效」（degraded 告警，不再静默）
- [ ] **preferred 语义**：勾两个渠道 + 优先+回退模式 → 观察尝试序列：前面的候选逐个 strict，
      只有最后一个候选才允许网关回退
- [ ] **粘性账号**：两个账号 + 粘性模式，连续发几条请求 → 历史里账号固定不变；
      把当前账号的 key 改错 → 账号级错误自动轮转到下一个账号且同一渠道重试

## 5. 流式与断连 💰

- [ ] 用 Cline/任意 OpenAI 客户端经代理发起流式对话 → SSE 正常输出
- [ ] 请求历史里该条记录回读到实际上游（流结束时从尾部元数据解析）
- [ ] **中途取消**：长回答进行中点客户端的停止 → 服务端日志无后续候选尝试，
      上游连接被取消（可在网络面板确认）——**客户端走了就不再扣额度**
- [ ] **预算封顶**：`config.json` 设 `failover.budgetMs: 8000` + 两个不可用渠道 → 8 秒左右返回错误而不是长时间挂起
